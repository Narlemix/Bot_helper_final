# HR Helper — веб-бот по увольнению

Готовый самостоятельный web-прототип. Работает в Docker и открывается в браузере.

## 1. Установка

Нужен Docker Desktop для Windows.

## 2. Первый запуск

В PowerShell:

```powershell
cd C:\путь\к\dismissal_web_bot
copy .env.example .env
docker compose build
docker compose up -d
```

Откройте:

http://localhost:8000

Проверка backend:

http://localhost:8000/api/health

## 3. Остановка

```powershell
docker compose down
```

## 4. Логи

```powershell
docker compose logs -f
```

## 5. SMTP

По умолчанию включён безопасный режим `DRY_RUN_EMAIL=true`: при подтверждении обращения бот не отправляет реальный e-mail.

Для реальной отправки отредактируйте `.env`:

```text
DRY_RUN_EMAIL=false
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=bot@example.com
SMTP_PASSWORD=your-password
SMTP_FROM=bot@example.com
RECIPIENT_EMAIL=dismissal@exc.ltd
```

После изменения `.env`:

```powershell
docker compose up -d --build
```

## 6. Что уже умеет

- русский язык;
- свободные формулировки;
- устойчивость к небольшим опечаткам (rapidfuzz + TF-IDF по символьным n-граммам);
- два сценария увольнения: офисный/административный персонал и **вахтовый персонал (вахтовики)** — каждый со своим маршрутом в кадровую службу;
- живые подсказки во время набора текста (typeahead): начинаете печатать «оформление» — под полем ввода появляются варианты вроде «оформление увольнения вахтовика», кликом или стрелками+Enter подставляются в поле;
- выбор: получить информацию или оформить обращение;
- сбор ФИО заявителя;
- сбор ФИО увольняемого сотрудника;
- сбор даты увольнения;
- дополнительный комментарий;
- подтверждение данных перед отправкой;
- SMTP-отправка с маршрутизацией по адресату конкретного сценария;
- веб-интерфейс без Node.js;
- Docker Compose.

### Добавление нового сценария увольнения

Чтобы добавить ещё один сценарий (например, увольнение сотрудников на удалёнке), допишите новый ключ
в `data/faq.json` по образцу `vahta_dismissal`: `name`, `recipient`, `keywords`, `example_questions`,
`safe_answer`. Классификатор и генератор подсказок подхватят его автоматически — код в `app/main.py`
трогать не нужно. Признак для различения сценариев — уникальные ключевые слова/фразы в каждом блоке
(например, «вахтовик» встречается только в вахтовом сценарии), поэтому для нового сценария добавляйте
явные отличительные слова, иначе классификатор может путать его с похожими.

### Подсказки при вводе (typeahead)

`GET /api/suggest?q=оформление` возвращает JSON `{"suggestions": [...]}` — до 6 фраз из ключевых слов и
примеров вопросов всех сценариев, отранжированных по похожести (нечёткое сравнение + бонус за совпадение
начала слова). Фронтенд (`app/static/app.js`) дергает этот эндпоинт с debounce 180мс, начиная с 2 символов,
и рисует выпадающий список над полем ввода, независимый от кнопок-подсказок, которые бот показывает после
каждого ответа.

### Маршрутизация писем на разных получателей

Раньше переменная `RECIPIENT_EMAIL` подменяла адрес получателя для **всех** сценариев сразу — это было
безопасно, пока сценарий был один, но сломало бы маршрутизацию с появлением второго. Теперь у каждого
сценария свой адрес по умолчанию (задаётся прямо в `data/faq.json`), а переопределить его можно точечно
через `.env`: `RECIPIENT_EMAIL_ADMIN_DISMISSAL` и `RECIPIENT_EMAIL_VAHTA_DISMISSAL` (см. `.env.example`).

## 7. Важно для продакшена

Перед публикацией в интернет нужно добавить HTTPS, домен, нормальное хранилище сессий/БД и секреты через защищённое хранилище. Текущая версия специально сделана простой для локального запуска и демонстрации.
