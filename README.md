# HR Helper — веб-бот по кадровым и административным обращениям

Готовый самостоятельный web-прототип. Работает в Docker и открывается в браузере.

Бот определяет тему обращения по свободному тексту (все 16 категорий из таблицы маршрутизации: увольнение офиса и вахты, справки, подотчётные средства, претензии, договоры, доверенности, подбор персонала и т.д.), уточняет, нужна ли справочная информация или оформление обращения, собирает недостающие данные и отправляет письмо на адрес, закреплённый именно за этой темой.

## 1. Установка

Нужен Docker Desktop для Windows.

## 2. Первый запуск

В PowerShell:

```powershell
cd C:\путь\к\dismissal_web_bot
copy .env.example .env
docker compose build
docker compose up -d
```

Откройте:

http://localhost:8000

Проверка backend:

http://localhost:8000/api/health

## 3. Остановка

```powershell
docker compose down
```

## 4. Логи

```powershell
docker compose logs -f
```

## 5. SMTP

По умолчанию включён безопасный режим `DRY_RUN_EMAIL=true`: при подтверждении обращения бот не отправляет реальный e-mail.

Для реальной отправки отредактируйте `.env`:

```text
DRY_RUN_EMAIL=false
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=bot@example.com
SMTP_PASSWORD=your-password
SMTP_FROM=bot@example.com
RECIPIENT_EMAIL=dismissal@exc.ltd
```

После изменения `.env`:

```powershell
docker compose up -d --build
```

## 6. Что уже умеет

- русский язык;
- свободные формулировки;
- устойчивость к небольшим опечаткам (rapidfuzz + TF-IDF по символьным n-граммам);
- **17 сценариев обращений**, покрывающих все 16 категорий из таблицы маршрутизации:

  - `vahta_hr_other` — приём/перевод/справки/изменения по вахте (кроме увольнения) → `kadry@exc.ltd`
  - `vahta_travel_compensation` — компенсация проезда вахты → `proezd@exc.ltd`
  - `vahta_weekend_registration` — срочное оформление вахтовика в выходной → `oformlenievixi@exc.ltd`
  - `admin_certificates` — справки (2-НДФЛ и т.д.) → `zak-spr-zp@exc.ltd`
  - `admin_accountable_funds` — подотчётные средства → `zap-ds@exc.ltd`
  - `admin_org_structure` — изменение оргструктуры → `izm-org-str-pod@exc.ltd`
  - `admin_new_employee` — оформление нового сотрудника → `RnE@exc.ltd`
  - `admin_lawyers` — юридические вопросы (доверенности, ЕГРЮЛ) → `lawyers@exc.ltd`
  - `admin_claims` / `admin_claims_over_50k` / `admin_claims_under_50k` — претензии → `claim@exc.ltd` / `claimover@exc.ltd` / `claimlower@exc.ltd`
  - `admin_power_of_attorney` — доверенности и печати → `Coorpao@exc.ltd`
  - `admin_supplier_contract` — договор с поставщиком → `sogl-dog-post@exc.ltd`
  - `admin_invoice_payment` — оплата счёта → `sogl-scheta@exc.ltd`
  - `admin_recruiting` — подбор персонала → `hr@exc.ltd`
- живые подсказки во время набора текста (typeahead) по всем сценариям сразу;
- выбор: получить информацию или оформить обращение;
- **два шаблона сбора данных**, задаются полем `template` в `data/faq.json`:
  - `dismissal` — структурированный шаблон (ФИО заявителя → ФИО увольняемого → дата увольнения → комментарий). Используется только в `admin_dismissal` и `vahta_dismissal`.
  - `generic` — свободный шаблон (ФИО заявителя → описание запроса одним сообщением). Используется во всех остальных 15 сценариях.
- подтверждение данных перед отправкой;
- SMTP-отправка с маршрутизацией на адрес конкретного сценария (каждый сценарий — свой email, см. `data/faq.json` → `recipient`);
- веб-интерфейс без Node.js;
- Docker Compose.

### Добавление нового сценария обращения

Чтобы добавить ещё один сценарий (например, новую категорию из таблицы, которой пока нет, или изменившийся email
получателя), допишите новый ключ в `data/faq.json` по образцу любого из существующих: `name`, `recipient`, `keywords`,
`example_questions`, `safe_answer`, и (опционально) `template` — `"dismissal"` для сценариев, где нужно отдельно
спросить ФИО увольняемого и дату, `"generic"` (по умолчанию, можно не указывать) — если достаточно ФИО заявителя и
свободного описания запроса. Классификатор, генератор подсказок и сборщик данных подхватят его автоматически — код в
`app/main.py` трогать не нужно. Признак для различения сценариев — уникальные ключевые слова/фразы в каждом блоке
(например, «вахтовик» встречается только в вахтовых сценариях, «свыше 50 000» — только в претензиях больше 50 тыс.),
поэтому для нового сценария добавляйте явные отличительные слова, иначе классификатор может путать его с похожими.

**Известное ограничение:** при 17 близких по смыслу сценариях (много общих слов вроде «документы», «оформить»,
«справка») классификатор иногда путает соседние темы — например «перевод вахтовика в другое подразделение» может
уйти в `admin_org_structure` вместо `vahta_hr_other`, так как оба содержат слова «перевод» и «подразделение». В таких
случаях бот обычно сам замечает близкие альтернативы и переспрашивает (см. поле `alternatives` в ответе `/api/chat`
и текст «Я вижу несколько близких вариантов…»), но не всегда. Если увидите систематическую путаницу между двумя
сценариями — добавьте в `keywords` одного из них более явные отличительные фразы.

### Подсказки при вводе (typeahead)

`GET /api/suggest?q=оформление` возвращает JSON `{"suggestions": [...]}` — до 6 фраз из ключевых слов и
примеров вопросов всех сценариев, отранжированных по похожести (нечёткое сравнение + бонус за совпадение
начала слова). Фронтенд (`app/static/app.js`) дергает этот эндпоинт с debounce 180мс, начиная с 2 символов,
и рисует выпадающий список над полем ввода, независимый от кнопок-подсказок, которые бот показывает после
каждого ответа.

### Маршрутизация писем на разных получателей

Раньше переменная `RECIPIENT_EMAIL` подменяла адрес получателя для **всех** сценариев сразу — это было
безопасно, пока сценарий был один, но сломало бы маршрутизацию с появлением второго. Теперь у каждого
сценария свой адрес по умолчанию (задаётся прямо в `data/faq.json`), а переопределить его можно точечно
через `.env`: `RECIPIENT_EMAIL_ADMIN_DISMISSAL` и `RECIPIENT_EMAIL_VAHTA_DISMISSAL` (см. `.env.example`).

## 7. Важно для продакшена

Перед публикацией в интернет нужно добавить HTTPS, домен, нормальное хранилище сессий/БД и секреты через защищённое хранилище. Текущая версия специально сделана простой для локального запуска и демонстрации.
